What this refactor is trying to do

The goal is not to make the repository clever. It is to stop every computer from inheriting every setting. A host should say which capabilities it needs, while hardware-specific facts remain in that host's own directory.

The core safety rule: first move existing settings without changing their values. Only after both existing hosts still evaluate do we remove packages, change behavior, or add the ThinkCentre. Structure changes and behavior changes should not be mixed casually.

Master document status

This file is the master record for the refactor. It describes the intended end state, decisions already made, completed migration slices, validation evidence, known problems, and the next gate. It must be updated whenever a slice changes the architecture or passes a validation milestone.

Current phase: system and Home Manager profiles are extracted. The desktop has rebuilt, rebooted, and passed its smoke test. Module ownership cleanup, username parameterization, and the two-list package split are complete. The graphical list is intentionally unchanged and now awaits a separate cruft audit. Android development has a documented design below, but no emulator or SDK configuration has been enabled yet.

The problem with the old shape

Every host

→

One giant shared configuration

configuration.nix Desktop, Steam, Bluetooth, packages, agents, VPNs, fonts, cron…

Same machine role

Desktop, laptop, and future server all receive nearly everything.

This is manageable with two similar workstations. It becomes dangerous with a third machine that should be an always-on agent host and lightweight media box.

Package strategy: two independent lists

Desktop + laptop

packages/graphical.nix

Used by nixos and laptop. This remains the convenient place to add browsers, editors, games, desktop utilities, development tools, and graphical applications.

Defined, not selected

packages/server.nix

Ready for the future mostly-server host but not imported by a current machine. It starts with remote administration, persistence/session tools, and agent tooling; TV/media packages wait for an explicit choice.

These lists do not inherit from one another. Intentional duplication of a few basics is acceptable: it keeps the server boundary visible and prevents a convenient desktop addition from silently bloating the ThinkCentre.

Android development without polluting the hosts

Boundary: Android is a development capability used on graphical hosts, not a reason to place an SDK, emulator image, NDK, Java runtime, libvirt stack, and graphics overrides in every login session.
Host responsibility

Hardware access only

The desktop and laptop already load kvm-amd from their hardware modules. No new shared system module appears necessary: keep ADB and the SDK in the development shell, and do not enable libvirt solely for the Android emulator or load both AMD and Intel KVM modules.

Development shell

nix develop .#android

Compose a pinned SDK with one platform, build-tools version, emulator, one x86_64 Google APIs system image, and a compatible JDK. Add one NDK only when a real project requires native builds. SDK environment variables exist only inside this shell.

Mutable user data

AVDs remain outside the Nix store

Emulator definitions and writable device state belong in ~/.android/avd. Projects own their own ignored local.properties; entering the shell must not overwrite it.

Validation gate

KVM must work first

On the current desktop, AMD-V is reported, kvm_amd is loaded, KVM is registered by the kernel, and udev expects /dev/kvm. The coding sandbox does not expose that device, so verify it from a normal host terminal before downloading a large emulator image; software emulation would be an unhelpful fallback.

The pinned NixOS release has removed programs.adb and no longer requires an adbusers group: systemd 258 supplies device access rules. The shell's platform tools can provide adb. Android Studio remains optional rather than a mandatory graphical package; the SDK and emulator should work with any editor.

Why the deleted emulator.nix was fragile

  • It installed two Android platforms, two build-tools releases, Google Play images, an NDK, Java, Watchman, Qt, graphics libraries, and emulator tools globally.
  • It loaded both kvm-intel and kvm-amd and enabled libvirt even though the Android emulator talks to KVM directly.
  • It globally forced an AMD Vulkan driver path, which was inappropriate for the laptop and brittle across graphics-driver changes.
  • It set ANDROID_EMULATOR_USE_SYSTEM_LIBS=1, bypassing the emulator's packaged libraries and making host-library mismatches more likely.
  • It expanded nix-ld and every interactive shell for a tool that should be entered explicitly per development session.

Implementation and proof sequence

  1. Verify that each GUI host exposes a usable /dev/kvm; fix firmware or host access separately if it does not.
  2. Add an android dev shell without changing either host closure, initially using one stable SDK/API and no NDK unless required.
  3. Evaluate and build the shell, then create one named AVD manually with avdmanager.
  4. Boot the AVD, confirm hardware acceleration, run adb devices, and build a small project before considering Android Studio or extra images.
  5. Only promote genuinely always-needed tools to packages/graphical.nix; never add them to the independent server list.

How we avoid breaking the machines

1

Record a baseline

Evaluate important options and package names for both existing hosts before moving the next layer.

2

Move one capability at a time

For example, move Home Manager agent configuration without simultaneously changing its settings or package versions.

3

Evaluate both hosts

Run focused nix eval checks, then nix flake check --no-build.

4

Build without switching

Use nix build --no-link only when the structure is stable. This creates no repo-root result symlink.

5

Switch one existing machine first

The user performs the switch. Test the desktop and remote access before touching the other machine.

6

Add ThinkCentre last

Only after the existing hosts remain equivalent do we add its hardware and select base + agents + media.

Things we should not do

  • Do not use hostname conditionals inside supposedly reusable profiles.
  • Do not give the ThinkCentre the workstation profile merely because a package is hard to reach.
  • Do not move settings and redesign their behavior in the same step.
  • Do not copy private keys, Tailscale state, or machine-local credentials.
  • Do not remove the compatibility path until all hosts evaluate and the current machines are smoke-tested.
  • Do not perform a rebuild or switch automatically during structural work.
  • Do not restore global Android SDK variables, host-specific Vulkan paths, both CPU vendors' KVM modules, or emulator library overrides.

Proposed remote-access architecture

Default path: use Tailscale as the private network and ordinary key-only OpenSSH as the login protocol. The new always-on machine becomes the normal destination; the Oracle machine remains a named legacy/off-site destination rather than defining the shared network architecture.
Transport

Tailscale + MagicDNS

Every selected host joins independently and keeps its own Tailscale state. SSH aliases use stable MagicDNS names instead of copied 100.x addresses. Oracle can stay enrolled as long as it remains useful.

Login

OpenSSH over the tailnet

Keep root and password login disabled, allow only the declared primary user, and authorize named public keys for the laptop/desktop and Moshi. Regular OpenSSH also remains the bootstrap transport for Mosh; do not enable a second Tailscale SSH identity system without a deliberate migration.

Firewall

Permit services, not the interface

Replace blanket trust of tailscale0 with explicit SSH TCP and Mosh UDP rules on that interface. Tailnet grants should independently restrict which personal devices may reach the new server. Tailscale's own discovery/transport port may remain open as required.

Client config

Named destinations

Move outbound aliases out of the generic Home Manager base into a small remote-hosts profile. Give the new machine its own alias and persistent known-host entry. Keep otto as the Oracle alias while it exists, but stop using a fixed tailnet IP and a known-hosts file in /tmp.

Legacy path

Oracle WireGuard is opt-in

The current WireGuard peer is an Oracle full-tunnel route to 132.145.49.251. It is disabled at boot today. If still useful, rename it as a legacy Oracle tunnel and select it only on intended client hosts; the new server should not import it. If Oracle is reachable through Tailscale, WireGuard is unnecessary for SSH.

Agent workflow

One obvious always-on target

Laptop, desktop, and phone connect to the new host by name, then attach to persistent tmux/Herdr sessions. Agent services must survive without a graphical login. Oracle remains a fallback or off-site workload host, not a hidden dependency of those sessions.

Provisioning wired: installation-day runbook

Fast path: the repo now builds a dedicated headless ISO as packages.x86_64-linux.wired-installer. It boots as wired-installer, obtains Ethernet through DHCP, advertises wired-installer.local, starts SSH automatically, and accepts only the dedicated desktop key. More importantly, it contains the complete prebuilt closure for a minimal installed wired system, so the ThinkCentre can be partitioned and installed beside the monitor with no Ethernet. It contains no private key and never modifies a disk automatically.
  1. Build the custom ISO, positively identify the Toshiba USB by model, serial, transport, and size, then verify the raw write with a read-back checksum.
  2. Boot the USB beside the monitor with Ethernet disconnected and follow wired-install-guide.html. The guarded wired-install helper requires the complete internal disk path, rejects removable disks, displays model/serial/size, and requires an exact ERASE /dev/… confirmation.
  3. The offline bootstrap uses GPT, a 1 GiB FAT32 EFI System Partition labeled WIRED_BOOT, and an ext4 root partition labeled WIRED_ROOT. It saves generated hardware facts, installs the bundled closure, and asks locally for a recovery password.
  4. Power off, remove the USB, move the machine to Ethernet, and boot. Connect using ssh -i ~/.ssh/id_ed25519_wired berkerz@wired.local; fall back to the router DHCP lease if mDNS is unavailable.
  5. Before touching disks, collect boot mode, disk model/serial, CPU/GPU, NIC name, TPM availability, and existing filesystem information.
  6. Choose storage deliberately. Plain ext4 is quickest and reboots unattended; LUKS protects agent credentials at rest but needs a boot-unlock plan, such as an initial passphrase followed by evaluated TPM2 enrollment.
  7. Partition only after the exact target disk is agreed, mount root and the EFI System Partition under /mnt, then run nixos-generate-config --root /mnt.
  8. Bring only the generated hardware-configuration.nix into hosts/wired/. Add a host module, Home Manager composition, nixosConfigurations.wired, and the independent server package list on the desktop repo.
  9. Before install, authorize the dedicated desktop public key and the intended phone/laptop keys in the installed host configuration. Never copy the private key into the repo or installer.
  10. Evaluate and build wired, push it, clone the pinned repo in the installer, and install with nixos-install --flake ...#wired.
  11. Set a local recovery password for the primary user before reboot. Remove the USB, boot locally, then run tailscale up once and authenticate the node.
  12. Verify LAN SSH, Tailscale/MagicDNS SSH, reboot survival, and Mosh before adding the TV session, media applications, or persistent agent workloads.

Boot default

multi-user.target

The media profile may install graphical capability while forcing the default boot target to headless mode. Installing GUI packages consumes disk space but does not mean the compositor or display manager is running.

System services

Machine-owned availability

Tailscale, OpenSSH, and Samba/NFS-style shares run as system services under multi-user.target. They never depend on a person logging in locally or on graphical-session.target.

User services

Persistent agent ownership

A lingering systemd user manager can supervise selected Herdr or tmux-based sessions after boot and across SSH disconnects. Interactive agents are not automatically persistent merely because their packages and hooks are installed; each desired recovery behavior needs an explicit unit.

GUI services

Session-owned state

Wayland compositor helpers, portals, panels, notifications, and wallpaper processes attach to graphical-session.target. Logging out stops them without touching the user manager's always-on agent units.

The implementation should add profiles/system/media-center.nix; it must not import the full workstation profile. Initially start and stop the graphical target manually. Friendly media-up/media-down commands or a remote control can be added only after the target transition is proven safe.

Mutable Hermes, declarative lifecycle

Hermes owns

~/.hermes

The setup wizard remains the source of truth for provider authentication, model and tool choices, skills, sessions, memories, platform configuration, and Hermes cron state. Rebuilds do not replace config.yaml, auth databases, or other writable runtime state.

NixOS owns

hermes-gateway.service

A minimal system service runs the pinned Hermes package as berkerz with the real home and system tool path. It starts at boot, consumes the imperative state, and restarts only after failure. No Hermes settings or credentials are rendered by Nix.

Host maintenance is not an agent cronjob. flake-reconcile.timer runs at 06:00 Europe/Istanbul, requires a root-owned clean checkout, fast-forwards origin/main anonymously, and switches only Git revisions that have not deployed successfully. It allows two hours for slow builds and records its success under /var/lib/flake-reconcile. It deliberately does not run nix flake update: dependency advancement must be committed upstream so the server never owns an unpublished lockfile.

~/dotfiles is consume-only on wired: root owns the checkout, ordinary user processes can read it, and the Hermes gateway additionally mounts it read-only inside its service namespace. Hermes may use a separate GitHub identity for explicitly authorized project repositories; the public dotfiles remote needs no credential and grants no push capability.

This makes write access to origin/main a root-equivalent deployment boundary for wired: committed Nix code can become the next system generation automatically. Branch protection and account security therefore matter more than adding an agent-level approval prompt.

The installer definition is a reusable recovery environment, separate from nixosConfigurations.wired. The first installed closure is intentionally a boring bootstrap, not the final profile composition. Its only embedded credential is the dedicated public key; passwords, private keys, Tailscale state, WireGuard material, and agent credentials remain absent. The installer and bootstrap carry a filtered recovery snapshot at /etc/wired/dotfiles; the real flake generation removes that snapshot, because future configuration should come from the Git repository.
